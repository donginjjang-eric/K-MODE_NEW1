# 크리에이터 수익·정산 센터 개편 설계

## 목표

현재 통화별 합계만 제공하는 화면을 크리에이터가 각 캠페인의 수익 발생 근거, 정산 진행 단계, 다음 행동을 이해할 수 있는 정산 센터로 개편한다.

## 검토한 방식

1. **실제 데이터 기반 정산 원장형(채택)**: 캠페인 참여 데이터의 보상액과 정산 상태를 캠페인별로 표시한다. 현재 데이터에 없는 지급 계정, 실제 지급일, 정산서 URL은 만들지 않는다.
2. **화면 전용 데모형**: 고정된 지급일과 결제 수단을 표시할 수 있으나 운영 데이터와 불일치할 수 있어 제외한다.
3. **지급 시스템 전체 구축형**: 계좌 등록, 지급 승인, 증빙 생성까지 포함하지만 이번 화면 개편 범위를 크게 넘으므로 후속 단계로 둔다.

## 화면 구조

### 1. 요약 영역

- 현지 통화별 예상 수익, 정산 대기, 정산 확정, 지급 완료를 같은 기준으로 표시한다.
- 통화가 여러 개인 경우 환율 합산을 하지 않고 통화별 카드를 유지한다.
- 가장 중요한 지급 완료 금액과 처리 중 금액이 시각적으로 구분되어야 한다.

### 2. 정산 진행 안내

- `성과 확인 → 정산 확정 → 지급 처리 → 지급 완료`의 네 단계를 보여준다.
- 정산 상태 `none`, `pending`, `confirmed`, `paid`를 단계에 대응시킨다.
- 현재 상태에 맞는 다음 행동 문구를 함께 표시한다.

### 3. 캠페인별 정산 내역

- 캠페인명, 카테고리, 보상액, 현지 통화, 정산 상태, 최근 갱신일을 표시한다.
- 각 항목은 해당 미션 상세 화면으로 연결한다.
- 기본 보상과 성과 보너스를 분리할 근거 데이터가 없으므로 이번 단계에서는 `확정 보상` 한 항목으로 표시한다.
- 취소된 캠페인과 금액을 해석할 수 없는 항목은 정산 원장에서 제외한다.

### 4. 지급 정보 안내

- 아직 지급 계정 저장 기능이 없다는 점을 명확히 표시한다.
- 지급 방식 및 계정 등록 기능은 후속 기능으로 안내하고, 현재는 운영팀 확인 방식임을 설명한다.
- 존재하지 않는 지급일이나 정산서 다운로드 버튼은 노출하지 않는다.

## 데이터 구조

- 기존 `getCreatorSettlementSummary`는 상단 통화별 요약에 그대로 사용한다.
- 새 조회 함수는 로그인한 크리에이터 소유의 참여 항목만 가져온다.
- 반환 항목은 참여 ID, 캠페인 제목과 카테고리, 참여 상태, 예상 보상, 정산 상태, 갱신일로 제한한다.
- 금액 파싱과 통화 구분은 기존 `creator-rewards` 규칙을 재사용한다.

## 상태 및 예외 처리

- 내역이 없으면 캠페인 성과가 확정된 뒤 이 화면에 나타난다는 빈 상태를 제공한다.
- 알 수 없는 정산 상태는 `확인 필요`로 표시한다.
- 여러 통화는 절대 합산하지 않는다.

## 검증

- 정산 항목 변환과 상태 단계 매핑을 단위 테스트한다.
- 데이터 조회가 크리에이터 ID로 범위를 제한하는지 계약 테스트한다.
- 정산 화면이 요약, 진행 단계, 캠페인별 내역, 지급 안내를 포함하는지 계약 테스트한다.
- 전체 테스트와 Next.js 운영 빌드를 실행한다.
- 배포 후 운영 주소에서 데스크톱 화면을 확인하고 가능한 경우 모바일 화면도 확인한다.
